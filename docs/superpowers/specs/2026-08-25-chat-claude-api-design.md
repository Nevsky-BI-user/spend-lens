# Чат з Claude по API у spend-lens — дизайн

Дата: 2026-08-25 · Статус: погоджено, чекає на план впровадження

## Навіщо

Дві мети, і порядок між ними важливий.

1. **Навчальна (головна).** Автор проходить курс Claude Platform 101 і хоче
   набити руку на справжній інтеграції з Claude API, а не на прикладах із
   документації. Тому проєкт має торкнутися всіх примітивів курсу власноруч:
   перший виклик, вибір моделі, системний промпт, стрімінг, tool use,
   prompt caching, облік токенів і обробка помилок.
2. **Продуктова (побічна).** Дашборд отримує вкладку «Чат»: ad-hoc питання по
   власних агрегатах витрат плюс поради з оптимізації з готовим промптом назад
   у Claude Code.

Головна мета диктує форму роботи: не одне велике впровадження, а сходинки, де
кожна запускається й дає видимий результат, і де функції, у яких живе саме API,
лишаються порожніми — з коментарем-завданням і тестом, який має позеленіти.

Побічна вигода саме цього проєкту: ціна власного коду одразу видно на тому
самому дашборді, який її і рахує. Забуте кешування чи зайвий виток інструмента
стають числом у `chat_usage`, а не абстракцією з документації.

## Погоджені рішення

| Питання | Рішення |
|---|---|
| Де працює чат | і на GitHub Pages, і локально в `npm run dev` |
| Проксі | Supabase Edge Function (той самий JWT і allow-list, що вже є) |
| Джерело даних | поточний зріз на екрані + інструменти для дозапиту |
| Роль чату | і питання по даних, і поради з оптимізації |
| Кошти | облік у `chat_usage` + денний ліміт |
| Розподіл роботи | каркас, UI, міграція, тести — Клод; функції з API — автор |

## Архітектура

Ключове спостереження з коду: `fetchSnapshot()` уже тягне в браузер **увесь**
масив (усі дні, сесії, проєкти), а `web/src/lib/analytics.js` — це чисті
функції без DOM. Отже все, що чат мав би «дізнатися про дані», уже лежить у
памʼяті вкладки й уже вміє рахуватися тими самими функціями, що малюють вкладки.

Звідси головне рішення: **агентний цикл живе в браузері, edge-функція лишається
без стану.**

```
браузер                          edge function              Anthropic
  │ context = вижимка зрізу
  │ (функціями analytics.js,
  │  тими самими, що й вкладки)
  ├── POST /chat {messages, context} ──►
  │        Bearer <supabase JWT>   │ 1. JWT + allowed_users
  │                                │ 2. денний ліміт з chat_usage
  │                                │ 3. system + tools + ключ ──►
  │  ◄──────── SSE-релей ──────────┤  ◄──── стрім ─────────────┤
  │                                │ 4. запис у chat_usage
  │ stop_reason: tool_use?
  │   виконую інструмент ЛОКАЛЬНО над снапшотом
  │   і шлю наступний POST з tool_result
```

Наслідки:

- Функція не звертається до таблиць витрат узагалі. Service-role їй потрібен
  лише для двох запитів до `chat_usage`: прочитати суму за сьогодні й дописати
  рядок.
- Уся аналітика лишається в одному місці, тому **чат фізично не може назвати
  число, яке суперечить вкладці**: він отримує рівно те, що порахувала
  `analytics.js`.
- Нічого не дублюється в Deno. Обробник написаний на вебстандартах
  (`Request`/`Response`/`fetch`), адаптери — `Deno.serve` для Supabase і
  `node:http` для `npm run dev`, по десятку рядків кожен.
- Ціна за це чесна: кожен виток циклу пересилає всю розмову наново. Гаситься
  `cache_control` на системному промпті й блоці контексту.

Модель за замовчуванням — `claude-sonnet-5`, назва в змінній середовища
`CHAT_MODEL`, щоб порівняння моделей не вимагало правки коду.

## Файли

Позначка «вправа» означає: Клод створює файл із сигнатурами, коментарями-
завданнями й тестами, тіла функцій пише автор.

| Файл | Що робить | Хто пише |
|---|---|---|
| `chat/hello.mjs` | навчальний скрипт: голий `fetch` до Messages API, друк відповіді й `usage` | вправа |
| `chat/dev-server.mjs` | адаптер `node:http` для локального режиму | Клод |
| `chat/tests/*.test.mjs` | `node --test`, без мережі й React | Клод |
| `supabase/functions/chat/index.ts` | адаптер `Deno.serve` | Клод |
| `supabase/functions/_shared/handler.mjs` | обробник запиту: auth → ліміт → виклик → релей → облік | Клод (каркас), вправа (крок виклику) |
| `supabase/functions/_shared/anthropic.mjs` | виклик Messages API, розбір SSE, `cache_control` | вправа |
| `supabase/functions/_shared/cost.mjs` | вартість відповіді з `usage` | вправа |
| `supabase/functions/_shared/limit.mjs` | сума за день і запис у `chat_usage` | Клод |
| `supabase/migrations/003_chat.sql` | таблиця `chat_usage` + RLS | Клод |
| `web/src/lib/chatContext.js` | вижимка поточного зрізу для промпта | Клод |
| `web/src/lib/chatTools.js` | описи інструментів + виконавці над снапшотом | Клод |
| `web/src/lib/chatClient.js` | цикл інструментів, стрім у React-стан | вправа |
| `web/src/components/ChatTab.jsx` | UI вкладки | Клод |

`_shared/` — документована угода Supabase про спільний код функцій, тому
Node-адаптер і Deno-адаптер імпортують звідти той самий файл, а не копію.

Тестованість вправ забезпечує підстановка залежності: `callAnthropic` приймає
`fetch` першим аргументом, тож тест підсовує заглушку й перевіряє форму запиту
та розбір стріму без мережі й без ключа.

## Контекст і інструменти

У промпт іде стисла вижимка **поточного зрізу** (період / день / проєкт із
глобального фільтра): KPI, денний ряд, топ проєктів, моделей і сесій, знайдені
аномалії. Орієнтовно 1,5 тис. токенів.

Інструменти виконуються в браузері над снапшотом; кожен — обгортка над наявною
функцією, нової математики нуль:

| Інструмент | Віддає | Поверх чого |
|---|---|---|
| `get_slice` | KPI, денний ряд, топи для іншого періоду чи проєкту | `filterSnapshot` + `computeKpis` + `projectsByCost` |
| `get_sessions` | сесії з вартістю, моделлю, прапорцями | `analyzeSessions` + `sessionFlags` |
| `get_session` | одна сесія детально + дайджест «що відбувалося» | `sessions[]` + `digest.js` |
| `get_findings` | знахідки вкладки «Дії» та аномалії днів | `buildRecommendations` + `detectAnomalies` |

Стеля — **чотири витки інструментів на питання**, далі модель відповідає тим, що
назбирала. Без стелі один невдалий інструмент крутить цикл, доки не зʼїсть
денний ліміт.

## Системний промпт

Українською, три жорсткі правила:

1. Числа беруться лише з блоку контексту й `tool_result`. Рахувати самому —
   заборонено.
2. Кожне число називає період і валюту.
3. Коли відповідь переходить у пораду — наприкінці готовий промпт для Claude
   Code у блоці коду, тим самим стилем, що вкладка «Дії».

## UI

Сьома вкладка «Чат» поруч із «Дії». Глобальні фільтри в шапці спільні з рештою
вкладок: видно, який саме зріз бачить чат, і питання «а якщо взяти 7 днів»
вирішується перемиканням фільтра, а не суперечкою з моделлю.

Історія розмови живе в памʼяті вкладки й гине з перезавантаженням. Внизу завжди
видно витрачене за сьогодні й ліміт.

## Облік, ліміт, помилки

`chat_usage`: час, email, модель, чотири види токенів, вартість, кількість
витків. RLS на читання — той самий allow-list; запис — лише service-role
зсередини функції.

`CHAT_DAILY_LIMIT_USD` (дефолт 1) перевіряється **до** виклику Anthropic.

| Ситуація | Поведінка |
|---|---|
| немає `ANTHROPIC_API_KEY` | вкладка каже «чат вимкнено», решта дашборда працює |
| користувач не в allow-list | 403 |
| перевищено денний ліміт | 429 і «сьогодні витрачено $X з $Y» |
| Anthropic перевантажений (529) | один повтор, далі повідомлення |
| обірваний стрім | часткова відповідь лишається на екрані з поміткою |

## Деплой і секрети

Ключ автор заводить сам на `console.anthropic.com` → API keys. Це окремий від
підписки на Claude Code рахунок (передплачені кредити), і саме тому витрати
чату не змішуються з тим, що збирає колектор.

Ключ кладеться в секрети edge-функцій Supabase (панель → Edge Functions →
Secrets) під іменем `ANTHROPIC_API_KEY`: префікс `SUPABASE_` у секретах
зарезервований. У браузер і в збірку він не потрапляє. Локально той самий ключ
лежить у `web/.env.local` (уже під `.gitignore`) і читається Node-адаптером.

Деплой самої функції — `npx supabase functions deploy chat`. Це перше місце в
проєкті, де README більше не обходиться самими вебінтерфейсами, тож розділ
налаштування Supabase доповнюється кроком із CLI. Свідомий компроміс: інші
варіанти проксі (Cloudflare, Vercel) вимагали б ще одного провайдера й ручної
перевірки JWT через JWKS — більше коду заради тієї самої безпеки.

## Тести

У проєкті тестів зараз немає, тому заводиться мінімум без нових залежностей —
`node --test` (Node 24 вміє сам). Покриваються дві чисті речі: збирач контексту
й виконавці інструментів (снапшот-фікстура на вході, JSON на виході), плюс
вправи через підставлений `fetch`. Окремий тест звіряє ціни в
`_shared/cost.mjs` з `collector/pricing.json`, щоб вони не розійшлися.

## Сходинки

Кожна запускається й дає видимий результат. Сходинки 1–3 не потребують ні
Supabase, ні деплою — чистий Node на локальній машині, тобто помилятися дешево.

| # | Що | Критерій готовності |
|---|---|---|
| 1 | `chat/hello.mjs`: перший виклик | у консолі відповідь і `usage`; видно заголовки й `anthropic-version` |
| 2 | стрімінг | той самий скрипт друкує текст по шматках, SSE-події розібрані руками |
| 3 | системний промпт + `chatContext.js` | у консолі відповідь на питання по справжньому зрізу |
| 4 | edge-функція: auth, секрет, релей | вкладка «Чат» відповідає на Pages і локально |
| 5 | цикл інструментів | питання про сесію поза зрізом дає правильну відповідь |
| 6 | кешування, облік, ліміт | у `chat_usage` видно cache-read; 429 при перевищенні |

## Чого свідомо не робимо

- Не зберігаємо історію розмов у базі.
- Не даємо моделі SQL і прямого доступу до таблиць.
- Не робимо вибір моделі в UI — лише змінна середовища.
- Не чіпаємо колектор і схему `usage_days` / `sessions_agg`.
