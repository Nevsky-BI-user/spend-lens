# Виправлення інструкцій репозиторію — пріоритезований чекліст

Знахідки аудиту агент-інструкцій (CLAUDE.md, .claude/, docs/, README, seed).
Кожен пункт: чому це проблема → конкретна правка. Пріоритети:
**П1** — вводить в оману або небезпечно; **П2** — дисципліна, що вже ламалась;
**П3** — гігієна.

## П1 — небезпечне / хибне

- [ ] **1. Переписати README.md — це досі шаблон стартера, і він радить
  деплой у прод.** README описує «порожній застосунок» і в «Getting started»
  каже запускати `npm run dev` — команду, яка в цьому проєкті ДЕПЛОЇТЬ У
  ЖИВИЙ застосунок і яку PreToolUse-хук у `.claude/settings.json` блокує.
  Людина або агент, що читає лише README (нова сесія іншого інструмента,
  колега), отримує пряму інструкцію зробити заборонене. *Правка*: замінити
  вміст на короткий README проєкту: що це за застосунок; розробка UI —
  `npm run dev:ui` (демо-режим, без бекенду); попередження, що `npm run dev`
  і `rayfin up` деплоять у прод і виконуються лише за окремою процедурою
  (посилання на скіл deploy-checklist); мапа документації → `docs/`,
  правила агентів → CLAUDE.md; актуальна структура тек (поточна в README
  не збігається з репо).

- [ ] **4. Застаріла заява про двох адміністраторів + хибна назва тесту
  adminList у коментарях.** (а) CLAUDE.md «Поточний стан» стверджує «двоє
  адміністраторів», але список `ADMIN_EMAILS` у `rayfin/data/schema.ts` і
  `src/services/adminConfig.ts` знову з ОДНОГО запису (за коментарем у
  schema.ts — рішення користувача від 2026-08-12, bus factor 1). Той, хто
  вірить CLAUDE.md, хибно вважає ризик закритим. (б) Коментарі в обох файлах
  посилаються на тест `src/__tests__/adminList.test.ts`, якого не існує;
  сам збіг списків насправді вже перевіряє `schemaPolicy.test.ts` (тест
  «список адміністраторів у схемі збігається зі списком у UI»).
  *Правка*: у CLAUDE.md виправити на фактичну кількість із приміткою про
  bus factor; виправити назву тесту в коментарях обох файлів (або винести
  цей тест у `adminList.test.ts`), а не писати дубль.

- [ ] **3. Полагодити захардкоджені шляхи в seed-скриптах.**
  `seed/parse_dictionary.py` (`SRC` — Excel у Downloads конкретного
  користувача; `OUT_DIR` — стара тека `C:\github\…`) і
  `seed/build_structure.py` (`SEED` — та сама стара тека) вказують на
  розташування, де репозиторію ВЖЕ НЕМАЄ (тепер `C:\azure_repos\…`).
  Наступний запуск або впаде, або мовчки запише вихід у чужий клон.
  *Правка*: `OUT_DIR`/`SEED` виводити від файлу скрипта
  (`os.path.dirname(os.path.abspath(__file__))`); `SRC` — аргумент CLI
  (`sys.argv[1]`) з підказкою, якщо не задано. Кроком 1 це страхує і скіл
  `seed-refresh` із цього пакета, але правка в скриптах — першоджерело.

## П2 — дисципліна, що вже ламалась

- [ ] **2. Ротація «Поточного стану» в CLAUDE.md.** Розділ виріс до ~60
  рядків реліз-історії (2.11 → 2.12 → 2.13 з деталями компонентів) — це вже
  changelog, а не «поточний стан»: нова сесія платить контекстом за кожен
  рядок, а суть («що працює зараз, що відкрито») тоне. *Правка*: лишити
  ~10 рядків — актуальний стан, останню віху, відкриті теми і явні заборони
  (типу відхиленої гілки); історію релізів перенести в новий
  `docs/release-history.md` (додати його в мапу docs); дописати в шапку
  розділу правило ротації: «нова віха додається згори, все старше за дві
  віхи переїжджає в docs/release-history.md у тому ж коміті».

- [ ] **5. Штамп свіжості docs/data-model.md — частина правила «в тому ж
  коміті».** Шапка документа каже «Оновлено: 2026-08-12», хоча CLAUDE.md
  фіксує пізніші зміни (релізи до 2026-08-18), і правило «актуалізувати
  після КОЖНОЇ зміни схеми/довідника/правил у тому ж коміті» формально
  виконувалось без оновлення штампа. Прострочений штамп знецінює документ:
  читач не знає, чому вірити. *Правка*: у CLAUDE.md («Домовленості коду»)
  і в `.claude/rules/schema-db.md` дописати до правила data-model.md слова
  «включно зі штампом "Оновлено:" у шапці»; разово поправити сам штамп.
  Скіли `schema-change` і `seed-refresh` із цього пакета це вже вимагають;
  агент `docs-drift-auditor` — ловить.

- [ ] **7. Завендорити 7 глобально-згаданих скілів/агентів або дати інлайн-
  фолбеки.** CLAUDE.md і `.claude/rules/frontend.md` посилаються на
  глобальні (машинні) скіли `rayfin-bootstrap`, `kpi-data-entry-app`,
  `react-ux-mechanics`, `pbi-corporate-theme`, `ukrainian-ui-copy`,
  `model-orchestration` і глобальний субагент `ux-baseline-auditor`. У
  хмарних сесіях (Claude Code on the web) глобальної теки немає — усі сім
  посилань мертві, і сесія або мовчки пропускає правило, або гадає.
  *Правка*: для скілів, критичних цьому репо (`react-ux-mechanics`,
  `ukrainian-ui-copy`, `ux-baseline-auditor`) — скопіювати у
  `.claude/skills/` / `.claude/agents/` проєкту (проєктна копія має
  пріоритет і версіонується з кодом); для решти — додати біля згадки
  однорядковий інлайн-фолбек у стилі «немає скіла → мінімум такий: …»
  (для `model-orchestration` — «немає скіла/exec-агентів → виконуй сам,
  без делегування»).

## П3 — гігієна

- [ ] **6. AGENTS.md не згадує CLAUDE.md і правила безпеки.** AGENTS.md —
  вхідна точка для НЕ-Claude агентів (і частини інструментів, що читають
  саме його), але описує лише Rayfin-документацію/MCP: агент, що стартує з
  нього, не дізнається ні про заборону `npm run dev`, ні про спільне дерево,
  ні про git-протокол. *Правка*: додати на початок AGENTS.md блок: «Правила
  цього репозиторію — CLAUDE.md (обовʼязково): НІКОЛИ `npm run dev` /
  `rayfin up` (деплоять у прод; для UI — `npm run dev:ui`); git — окремі
  гілки, add лише явними шляхами, у теці працюють паралельні сесії
  (docs/parallel-sessions.md)».

- [ ] **8. Додати `paths`-фронтматер до `.claude/rules/fabric-cli.md`.**
  Три інші rules-файли мають `paths` і, як обіцяє CLAUDE.md, «підтягуються
  автоматично при роботі з відповідними файлами»; fabric-cli.md фронтматера
  не має, тож або вантажиться завжди (зайвий контекст), або не
  привʼязується взагалі — залежно від механізму, і в обох випадках не так,
  як задумано. *Правка*: додати фронтматер, наприклад
  `paths: ["rayfin/**", "docs/access-request-*.md"]` (деплой/пайплайни —
  місця, де реально потрібен fab CLI), а в CLAUDE.md лишити явну підказку
  «працюєш із fab CLI напряму → прочитай .claude/rules/fabric-cli.md».

- [ ] **9. Доповнити мапу docs у CLAUDE.md — 5 документів поза мапою.**
  Рядок docs/ у «Карті репозиторію» називає лише 4 файли; поза мапою:
  `parallel-sessions.md` (згаданий тільки в git-розділі),
  `access-request-notifications.md`, `access-request-pipeline-walkthrough.md`,
  `rayfin-feature-request.md`, `workspace-conventions.md` — плюс тека
  `docs/manual/` (збірка PDF-інструкції). Нова сесія не знаходить їх з
  «швидкого старту» і перевідкриває вже описане. *Правка*: розширити рядок
  docs/ у карті одним-двома рядками з призначенням кожного файлу (і
  згадкою docs/manual/); після пункту 2 сюди ж додасться
  `release-history.md`.
