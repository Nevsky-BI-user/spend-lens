# Звіт: аудит екосистеми скілів, аналіз проєктів і ринку

Дата: 2026-08-25. Обсяг: 2 проєктні репо, 4 скіл-бібліотеки + synced-набір claude.ai,
веб-дослідження ринку скілів. Це санітизована версія для публічного репо;
деталі проєктів — у приватному артефакті-звіті.

## 1. Стан екосистеми скілів

Скіли живуть у п'яти каналах одночасно: `powerbi-craft-marketplace` (9 плагінів,
56 скілів, найсвіжіше покоління), `pbi-skills` (45), `skills-transfer` (35, заморожений
транспортний знімок), корпоративний набір (3), synced на claude.ai (~25). Виміряний
дрейф: **37 із 45 спільних скілів мають розбіжні копії** (`scripts/drift-report-2026-08-25.txt`).

Найболючіше: synced-копії на claude.ai старіші за виправлення 2026-07-11 —
`dax-svg` там досі вчить ескейпінг без `%→%25` (відома причина «чорних комірок»),
`icon-set-manager` — незаповнений шаблон із неробочим Iconify-ендпоінтом.
**Саме тому «скіли не працюють» найчастіше у хмарних сесіях**: вони отримують
гірші версії, ніж локальні.

Рішення в пакеті: canonical = marketplace; `skill_drift_check.py` для контролю;
порядок оновлення каналів — у README.

## 2. Тригеринг: чому «не спрацьовує / спрацьовує не те»

Механіка: роутер бачить лише frontmatter-описи всіх скілів одночасно і обирає
найкращий лінгвістичний збіг. Знайдені та виправлені конфлікти:

| Конфлікт | Причина | Виправлення |
|---|---|---|
| `power-bi-dax-optimization` ніколи не спрацьовував | опис-етикетка без жодної тригерної фрази; `dax-measures` сам claims «optimize» | новий скіл `dax-optimization` — єдиний власник performance; «optimize» видалено з dax-measures |
| `dax-svg` крав запити Deneb | голі «намалюй», «візуалізуй» в описі | вісь «комірка vs канва» в першому реченні обох описів |
| межа «Do NOT trigger for SVG» не працювала | користувач ніколи не пише «SVG» — пише «спарклайн в таблиці» | межі переписані за наміром, додані україномовні фрази |
| `pbip-pr-reviewer` стріляв у будь-якому репо | тригери «review PR», «проаналізуй зміни» без скоупа | скоуп на наявність PBIP-артефактів (*.tmdl, .SemanticModel/ …) |
| дублікати каналів | плагін + копія + synced = 2-3 описи-конкуренти | правило «одне середовище — один канал» |

Інструменти закріплення: корпус тригер-проб (`routing/trigger-probe-corpus.md`),
методика живих `claude -p` проб (вже випробувана в marketplace: 37/39),
`claude plugin eval` для CI, `/skill-doctor` для моніторингу вживання.

## 4. «Мет Майк» і ринок скілів

**«Мет Майк» — з високою ймовірністю Matt Pocock** (`mattpocock/skills`, ~20k зірок,
у офіційному plugin-маркетплейсі; вірусні «скіли від Метта» в укр. тех-медіа).
Другий кандидат — YouTuber Matt Maher, але власного каталогу він не публікує.
Що варто запозичити в Покока: розділ user-invoked (slash) vs model-invoked скілів;
маленькі композитні скіли замість монолітів; «grilling»-примітив (допит перед
кодом — для DAX: грануляція, filter context, зв'язки — перед написанням міри);
одноразовий /setup-скіл на репо; CONTEXT.md зі спільним словником проєкту.

**Ринок (серпень 2026)**: офіційний шар (anthropics/skills ~141k зірок,
claude-plugins-official), community-шар (skills.sh — лідерборд інсталів,
aitmpl.com, superpowers, awesome-списки), комерційний шар без офіційного
магазину — Gumroad/Whop/власні лендінги: $14.99 за скіл, $39–99 пакети,
$99–167 бандли; реально продаються маркетинг/SEO/контент-паки у авторів
з аудиторією (кейс: $99-пак → $5–10k за місяці). **У ніші Power BI платних
скілів немає взагалі**: Microsoft (skills-for-fabric, MCP-сервери) і Kurt Buhler
(power-bi-agentic-development, GPL-3.0) — безкоштовні і покривають «сантехніку»,
не craft. Copilot закритий ліцензією $30/user/mo — Pro-only організації повністю
за бортом.

**Позиціювання**: powerbi-craft-marketplace вже найглибший у report-craft ніші
(per-visual механіка, SVG-in-DAX, Deneb, дизайн-системи, PBIP PR review —
цього немає ні в Microsoft, ні в Buhler). Реалістична стратегія: безкоштовне
ядро (лістинг у skills.sh, awesome-списках, заявка в claude-plugins-official) +
платний рівень: «Visual Craft Pack» ($49–99), B2B governance/CI-review
(команда/сідж-ціни), Copilot-readiness скіли. Монетизація в ніші тече через
навчання/консалтинг — скіли як лід-магніт.

## 5. Беклог нових скілів/агентів/воркфлоу (пріоритезовано)

**Зроблено в цьому пакеті**: dax-optimization (новий), recipes.md для dax-svg
(новий), 5 переписаних описів, дерево маршрутизації, корпус проб, drift-checker,
2 проєктні пакети (хуки/скіли/агент/FIXES).

**Наступна черга (висока віддача)**:
1. `trigger-probe` як воркфлоу-скіл у marketplace — автоматизація живих проб
   з корпусом і звітом промахів (уже є методика v0.1.4; це і продукт для ринку).
2. `release-bump` скіл для marketplace — версії plugin.json+marketplace.json,
   em-dash чейнджлог, validate_repo.py (16 релізів за 6 днів робилися руками).
3. Крос-реф лінк-чекер у validate_repo.py (123 посилання між скілами; 27 мертвих
   уже ловили руками).
4. `dax-grill` — grilling-примітив перед написанням міри (грануляція, контекст,
   зв'язки, очікуваний total) — запозичення в Покока з найбільшим ефектом на якість DAX.
5. Семантична модель/TMDL-авторинг і Power Query/M — найбільші тематичні прогалини
   бібліотеки (зараз нуль покриття; можна будувати поверх Microsoft Modeling MCP).
6. `skill-sync` воркфлоу: drift-check у cron + оновлення synced-набору claude.ai
   за один прохід.
7. Проєктні: docs-drift-auditor запускати щотижня (Routine); ui-variant-showcase
   для клієнтських погоджень А/Б/В; demo-parity-reviewer.

## 6. Метрики успіху

- First-pass hit rate корпусу проб ≥ 90% (зараз: конфліктні пари програвали систематично).
- `skill_drift_check.py` → exit 0 на всіх каналах після синхронізації.
- `/skill-doctor`: нуль скілів з нульовим вжитком серед кастомних через місяць.
